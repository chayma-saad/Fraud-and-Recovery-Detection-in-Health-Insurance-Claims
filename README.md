# Fraud and Recovery Detection in Health Insurance Claims

Machine-learning pipeline for flagging risky health-insurance claims **at submission time**, before they are paid, instead of recovering the money afterwards through manual review and clawback.

The project works on two independent datasets:

- **Al Hilal Takaful**: about 840k claims (2013–2016). The model predicts which claims will end up in the insurer's Recovery Report.
- **Jordan**: about 600k claims (2013–2017). The model predicts claims flagged by investigators as possible provider/policyholder collusion.

On top of the supervised models, an **adversarial self-play** stage trains a reinforcement-learning "fraudster" to find ways around the detector. The detector is then retrained against the attacks it discovered.

## Pipeline

| Phase | What it does | Notebook | Docs |
|---|---|---|---|
| 2. Data processing | Load and clean the raw Al Hilal Excel exports, join claims with beneficiaries, build `claims_ml_ready.csv` | `notebooks/data_processing.ipynb` | [docs/01_data_processing.md](docs/01_data_processing.md) |
| 3. Modeling | Time-based split (past → future); Logistic Regression, LightGBM and XGBoost on a heavily imbalanced target; SHAP explanations | `notebooks/02_modeling.ipynb` | [docs/02_modeling.md](docs/02_modeling.md) |
| 3b. Jordan modeling | Leakage-safe collusion-risk model on the Jordan dataset | generated by `scripts/build_jordan_modeling_notebook.py` | [docs/04_jordan_modeling.md](docs/04_jordan_modeling.md) |
| 4. Adversarial self-play | CTGAN synthetic claims → Gymnasium environment → PPO fraudster vs. an XGBoost defender → defender retrained (v2) | `notebooks/03_adversarial_selfplay.ipynb` | [docs/03_adversarial_selfplay.md](docs/03_adversarial_selfplay.md) |
| 4b. Jordan self-play | Same self-play setup on the Jordan dataset | `notebooks/05_jordan_adversarial_selfplay.ipynb` | [docs/05_jordan_adversarial_selfplay.md](docs/05_jordan_adversarial_selfplay.md) |

Only CTGAN trains on real claims. The RL environment sees nothing but synthetic claims sampled from CTGAN.

## Repository layout

```

  jordan/            Jordan data preparation
```

## Data

The `data/` folder is **not in this repository**. The files are several GB, and the claims and beneficiary records are confidential. The scripts expect this layout:

```
data/
  raw/utilization/      Al Hilal claims workbooks (.xlsx)
  raw/beneficiaries/    Al Hilal beneficiary workbooks (.xlsx)
  processed/            Generated CSVs (claims_ml_ready.csv, ...)
  processed/jordan_data/  Jordan dataset export
```

## Setup

```bash
python -m venv venv
# Windows: venv\Scripts\activate   |   macOS/Linux: source venv/bin/activate
pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu
```

The project was developed with Python 3.14 and the CPU-only build of PyTorch.

## Running

Each notebook is generated by a script in `scripts/`. For example:

```bash
python scripts/build_notebook.py           # Phase 2 – data processing
python scripts/build_modeling_notebook.py  # Phase 3 – modeling
```

To run the self-play pipeline, run the scripts in `scripts/selfplay/` (or `scripts/jordan_selfplay/`) in this order: `train_defender.py` → `train_ctgan.py` → `train_ppo.py` → `retrain_defender_v2.py`. Then generate the notebook with `build_selfplay_notebook.py`.
